## 1. 项目背景

### 1.1 行业背景

电商运营是一项高频、重复、数据密集型的工作。一个中小店铺的运营人员每天需要：登录后台查看昨日数据、计算核心指标、排查异常波动、翻看商品评论、回复差评、撰写运营日报。这些工作存在明显痛点：

1. **数据分散、取数门槛高**：GMV、转化率、客单价、退款率等指标散落在订单、流量、退款多个模块，运营不会写SQL。
2. **异常发现滞后**：某个商品销量暴跌、退款率飙升，往往要等几天才发现，错过处理窗口。
3. **归因靠猜**：发现销量下跌后，是流量减少、转化率下降、差评影响还是断货，缺乏系统化排查路径。
4. **评论处理耗时**：每天几十上百条评论，差评中藏着产品问题，人工难以聚类统计。
5. **日报周报重复**：格式固定的报告每天手动拉数、截图、写结论，耗时1-2小时。

### 1.2 项目定位

> **ShopPilot是一个基于MCP协议的电商运营垂直Agent。**
>
> 运营人员用自然语言与Agent对话，或由Agent每日定时自动执行，即可完成"数据查询 → 指标计算 → 异常检测 → 差评聚类 → 归因分析 → 报告生成 → 主动推送"的完整运营工作流。

本项目不是通用的NL2SQL工具，而是**内置电商业务指标体系和运营排查方法论的垂直Agent**：它理解GMV、转化率、退款率等业务概念，掌握异常归因的分析路径，并通过MCP协议标准化地接入数据查询、评论分析等工具能力。

### 1.3 项目目标

| 目标 | 说明 | 达成情况 |
|------|------|---------|
| 业务目标 | 将运营每日1-2小时的数据分析和报告工作压缩到10分钟 | ✅ 一键体检约30秒出报告 |
| 技术目标 | 实践MCP协议工具标准化、ReAct Agent自主归因、确定性与LLM分工 | ✅ 2个MCP Server + ReAct + 确定性异常扫描 |
| 求职目标 | 打造"垂直行业 + MCP + 业务闭环"的S级简历项目 | ✅ 已上线GitHub |

### 1.4 目标用户

| 角色 | 场景 | 核心诉求 |
|------|------|---------|
| 电商运营专员 | 每日看数、排查异常、写日报 | 不会SQL也能用自然语言取数、自动发现问题 |
| 店铺负责人 | 掌握店铺整体经营状况 | 每天收到结构化日报，异常第一时间预警 |
| 运营团队 | 评论洞察、选品参考 | 自动聚类差评痛点，追踪问题趋势 |

### 2.2 核心用户故事

**US-01：自然语言取数**
> 运营在对话框输入"昨天GMV多少"。Agent调用 get_metrics 工具查询，回答："昨日GMV为¥15,177。"

**US-02：异常自动归因**
> 运营点击"一键体检"。Agent先调 scan_anomalies 扫描全店，发现P1008保温杯差评率56%、P1006台灯疑似断货；对P1008调 cluster_reviews 聚出差评主题（包装破损8+快递暴力4+漏水6），对P1006查详情发现库存0已售罄；结论：P1008物流包装问题、P1006断货，给出补货和换快递建议。

**US-03：差评痛点洞察**
> 运营问"保温杯用户都在抱怨什么"。Agent调 cluster_reviews 输出：包装简陋8条、漏水5条、快递暴力4条、保温差3条，并附典型评论原文。

**US-04：自动日报+推送**
> 早上8点定时任务自动跑 generate_report：扫描异常→Agent归因→生成Word日报→入库→发现7条高级异常→推送告警到飞书群。

## 3. 业务指标体系

Agent内置以下电商指标定义（全部确定性Python计算，LLM不参与算数字）：

| 指标 | 计算公式 |
|------|---------|
| GMV（成交额） | SUM(订单实付金额)，退款前口径 |
| 客单价 | GMV / 订单数 |
| UV（独立访客） | 流量表UV求和 |
| 转化率 | 下单UV数 / UV |
| 加购率 | 加购数 / UV |
| 退款率 | 退款订单数 / 总订单数 |
| 差评率 | 评分≤3星评论数 / 总评论数 |
| 环比 | (本期值 - 上期值) / 上期值 |

**异常判定规则（可配置，在 config.py 统一管理）：**
- 差评率 ≥ 15% → 异常（≥30%为high）
- 退款率 ≥ 10% → 异常
- GMV环比下跌 ≥ 30% → 异常（若库存0已售罄则判定为疑似断货）
- 全店差评率环比上升 ≥ 8个百分点 → 异常
- 全店退款率环比上升 ≥ 5个百分点 → 异常

**归因决策路径（Agent System Prompt 内置）：**
```
异常商品
├── 库存为0且已售罄 → 断货（建议补货）
├── 库存正常 → 看差评主题聚类
│   ├── 主题集中破损/漏水/快递 → 物流包装问题
│   └── 主题集中质量/尺码/色差 → 商品与详情页问题
└── GMV跌但差评正常 → 流量/渠道问题
```

## 4. 非功能需求

### 4.1 性能

| 指标 | 要求 | 实际 |
|------|------|------|
| 单次取数问答 | < 10秒 | ✅ 约5-8秒（含流式） |
| 全量异常体检 | < 60秒 | ✅ 约25-35秒（3轮LLM+并行工具调用） |
| 日报生成 | < 60秒 | ✅ 约30-40秒 |

### 4.2 准确性

| 指标 | 目标 | 实际 |
|------|------|------|
| 指标计算正确率 | 100% | ✅ 确定性Python，不允许错 |
| 预埋异常召回率 | ≥80% | ✅ 2/2 预埋负面异常（物流破损、断货）全部召回 |
| 数字编造率 | 0% | ✅ 所有数字来自工具返回，LLM不算数 |

### 4.3 安全性

- 数据查询工具为**只读**，Agent无法修改业务数据
- API Key通过.env管理，.gitignore排除，不入库不入日志
- MCP Server独立进程，Agent通过stdio协议调用，无直接数据库写权限

### 4.4 可观测性

- 每次Agent调用记录：工具名、参数、返回摘要到 `logs/trace_日期.log`
- 体检结果入库 `daily_reports` 表，可历史回看
- 异常推送有成功/失败日志

## 5. 项目边界

### 5.1 已交付范围

- ✅ SQLite模拟电商数据库（45天数据，8商品/5渠道，含3个预埋异常）
- ✅ 2个自研MCP Server：ecomdb（7个数据工具）、review（差评聚类）
- ✅ DeepSeek + LangGraph ReAct Agent（对话问答 + 一键体检）
- ✅ 确定性指标计算 + 阈值异常扫描
- ✅ 差评LLM主题聚类
- ✅ Streamlit三Tab界面（智能问答/一键体检/经营图表，流式输出）
- ✅ Word日报生成（python-docx）
- ✅ 异常主动推送（飞书/钉钉webhook）
- ✅ 定时任务（APScheduler每天8点）
- ✅ FastAPI REST接口
- ✅ Trace日志 + 历史报告入库 + 配置集中管理

### 5.2 范围外

- ❌ 对接真实电商平台API（淘宝/抖音/拼多多）
- ❌ 多用户/权限/账号系统（纯CRUD，无技术含量）
- ❌ 在线实时数据流（用历史静态数据）
- ❌ 自动执行营销动作（改价、投流、上架）
- ❌ 模型微调与本地化部署
- ❌ 多轮对话记忆（MVP单轮）
