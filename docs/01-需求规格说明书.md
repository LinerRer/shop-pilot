## 1. 项目背景

### 1.1 行业背景

电商运营是一项高频、重复、数据密集型的工作。一个中小店铺的运营人员每天需要：登录后台查看昨日数据、计算核心指标、排查异常波动、翻看商品评论、回复差评、撰写运营日报。这些工作存在明显痛点：

1. **数据分散、取数门槛高**：GMV、转化率、客单价、退款率等指标散落在订单、流量、退款多个模块，运营不会写SQL，依赖数据分析师排期。
2. **异常发现滞后**：某个商品销量暴跌、退款率飙升，往往要等几天后台数据明显下滑才发现，错过处理窗口。
3. **归因靠猜**：发现销量下跌后，是流量减少、转化率下降、差评影响还是竞品促销，缺乏系统化的排查路径。
4. **评论处理耗时**：每天几十上百条评论，差评中藏着产品问题（如"尺码偏小""物流破损"），人工难以聚类统计。
5. **日报周报重复**：格式固定的报告每天手动拉数、截图、写结论，耗时1-2小时。

### 1.2 项目定位

> **ShopPilot是一个基于MCP协议的电商运营垂直Agent。**
>
> 运营人员用自然语言与Agent对话，或由Agent每日定时自动执行，即可完成"数据查询 → 指标计算 → 异常检测 → 归因分析 → 评论洞察 → 报告生成"的完整运营工作流。

本项目不是通用的NL2SQL工具，而是**内置电商业务指标体系和运营排查方法论的垂直Agent**：它理解GMV、转化率、退款率等业务概念，掌握异常归因的分析路径，并通过MCP协议标准化地接入数据查询、评论分析、报告生成等工具能力。

### 1.3 项目目标

| 目标 | 说明 |
|------|------|
| 业务目标 | 将运营每日1-2小时的数据分析和报告工作压缩到10分钟 |
| 技术目标 | 实践MCP协议工具标准化、LangGraph有状态工作流、Agent自主归因决策 |
| 求职目标 | 打造"垂直行业 + MCP + 业务闭环"的S级简历项目，匹配杭州电商AI岗位 |

### 1.4 目标用户

| 角色 | 场景 | 核心诉求 |
|------|------|---------|
| 电商运营专员 | 每日看数、排查异常、写日报 | 不会SQL也能用自然语言取数、自动发现问题 |
| 店铺负责人 | 掌握店铺整体经营状况 | 每天收到结构化日报，异常第一时间预警 |
| 运营团队 | 评论洞察、选品参考 | 自动聚类差评痛点，追踪问题趋势 |

### 2.2 核心用户故事

**US-01：自然语言取数**
> 运营在对话框输入"昨天和前天的GMV分别是多少，跌了吗？"。Agent识别意图为指标查询，调用数据工具查询两天销售额，计算环比，回答："昨日GMV为¥48,230，前日为¥56,800，环比下降15.1%。"

**US-02：异常自动归因**
> 运营点击"一键体检"。Agent发现商品P1008销量环比下跌42%，自动展开排查：该商品UV下跌35%（流量问题）→ 进一步发现主要来自搜索渠道流量下降 → 检查评论发现近3天差评新增8条，集中在"收到的商品有破损" → 结论：可能是物流破损导致搜索权重和转化双降，建议检查包装和物流。

**US-03：差评痛点洞察**
> 运营问"最近用户都在抱怨什么？"。Agent对近7天差评做情感分析和语义聚类，输出：物流破损23条、尺码偏小15条、色差8条、客服态度5条，并列出每类的典型评论原文。

**US-04：自动日报**
> 早上9点运营点击"生成昨日日报"。Agent自动拉取数据、算指标、检测异常、分析评论、生成图表，10秒后输出一份Word日报：核心指标看板、3项异常预警（含归因）、差评热点、今日建议。

## 3. 业务指标体系（领域知识）

Agent内置以下电商指标定义，保证分析的专业性：

| 指标 | 计算公式 |
|------|---------|
| GMV（成交额） | SUM(订单实付金额)，含退款前口径 |
| 客单价 | GMV / 订单数 |
| UV（独立访客） | 流量表去重访客数 |
| 转化率 | 下单UV数 / UV |
| 加购率 | 加购数 / UV |
| 退款率 | 退款订单数 / 总订单数 |
| 差评率 | 评分≤3星评论数 / 总评论数 |
| 环比 | (本期值 - 上期值) / 上期值 |

**异常判定规则（可配置）：**
- GMV/销量环比下跌超过 30% → 异常
- 退款率单日超过 10% 或环比上升超过50% → 异常
- 差评率单日超过 15% → 异常
- 单商品指标偏离其近7日均值2个标准差 → 异常

**归因分析路径（Agent决策树）：**
```
销量下跌
├── 流量侧：UV是否下降？
│   ├── 整体UV降 → 渠道维度拆解（搜索/推荐/直播/广告）
│   └── 单商品UV降 → 是否被降权/下架/库存售罄
├── 转化侧：UV稳定但转化降？
│   ├── 价格变动？
│   ├── 差评突增？→ 评论聚类找原因
│   └── 库存/发货问题？
└── 商品侧：是否竞品促销/季节性因素
```

## 4. 非功能需求

### 4.1 性能要求

| 指标 | 要求 |
|------|------|
| 单次取数问答响应 | < 8秒 |
| 全量异常体检（扫描所有商品） | < 60秒 |
| 日报生成（含图表+Word） | < 30秒 |
| 500条评论情感分析 | < 30秒（批量并发） |

### 4.2 准确性要求

| 指标 | 目标值 | 测量方式 |
|------|--------|---------|
| 自然语言取数正确率 | ≥ 85% | 50个标准测试问题，人工核对结果 |
| 异常检测召回率 | ≥ 80% | 数据中预埋10个异常，检测出≥8个 |
| 异常误报率 | ≤ 20% | 检出的异常中误报占比 |
| 评论情感分析准确率 | ≥ 85% | 人工标注100条评论作测试集 |
| 指标计算正确率 | 100% | 指标公式为确定性逻辑，不允许出错 |

### 4.3 安全性要求

- 数据查询工具为**只读**，Agent无法修改/删除任何业务数据
- MCP工具对SQL做白名单限制（只允许SELECT），拦截写操作
- API Key通过.env管理，不入库不入日志

### 4.4 可观测性要求

- 每次Agent决策记录：意图分类结果、选择的工具、推理过程
- 每次MCP工具调用：Server名、工具名、参数、返回摘要、耗时
- 每次LLM调用：模型、token消耗、延迟
- 通过Langfuse面板可完整回放一次归因分析的决策链路

## 5. 项目边界

### 5.1 MVP范围内

- ✅ 内置SQLite模拟电商数据库（约90天数据，含商品/订单/流量/评论/退款5张表）
- ✅ 3个自研MCP Server：数据查询、评论分析、报告生成
- ✅ LangGraph编排的对话式取数 + 异常归因 + 日报两大工作流
- ✅ 评论情感分析与语义聚类
- ✅ Plotly图表 + python-docx日报导出
- ✅ Streamlit交互界面
- ✅ Langfuse全链路Trace
- ✅ 50题测试集与准确率评估

### 5.2 MVP范围外

- ❌ 对接真实电商平台API（淘宝/抖音/拼多多）
- ❌ 真实定时调度（用按钮触发模拟）
- ❌ 多用户/权限系统
- ❌ 在线实时数据流（用历史静态数据）
- ❌ 自动执行营销动作（改价、投流、上架）
- ❌ 模型微调与本地化部署
