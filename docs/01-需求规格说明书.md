# ShopPilot 需求规格说明书

版本 v2.0，2026-10-13

## 为什么做这个

电商运营每天的工作很大一块是重复的：看昨天的数据、算指标、发现哪个商品不对劲、翻评论找原因、写日报。这些事不复杂但碎，运营不会 SQL，取数要等数据分析师排期，等发现异常时往往已经晚了几天。

这个项目就是做一个懂电商的 Agent：运营用大白话问，或者让它每天自动跑，它自己查数、算指标、找异常、翻评论、给原因、出报告。不是通用的 NL2SQL 工具——通用工具只能查数，这个内置了电商的指标定义和异常归因思路。

## 目标用户

- 电商运营专员：日常看数、排查异常，不用等 SQL
- 店铺负责人：每天收一份结构化日报，异常及时知道
- 运营团队：差评自动聚类，不用人工一条条看

## 功能

### 已实现

**数据查询**：自然语言问 GMV、订单量、客单价、UV、转化率、加购率、退款率、差评率，支持按日期范围和按商品查。所有指标是 Python 确定性计算，不是 LLM 算的。

**异常检测**：阈值写死在配置里——差评率 ≥15%、退款率 ≥10%、GMV 环比跌 ≥30%、库存为 0 判定疑似断货。全店扫描后输出异常清单。

**异常归因**：Agent 拿到异常清单后，对高级别异常自动下钻，调商品详情和差评聚类工具，区分是断货、物流破损还是商品质量问题，给可执行建议。

**差评主题聚类**：独立的 MCP Server，从数据库读差评，交给 DeepSeek 聚成主题（如"包装破损 8 条""漏水 5 条"），输出主题、数量、典型评论。体检和日报都会引用。

**Word 日报**：汇总异常表格 + AI 根因分析，生成 .docx，写完自动存数据库。

**异常推送**：日报跑完如果有高级别异常，走飞书/钉钉 webhook 推告警；没配 webhook 就模拟打印到控制台。

**定时任务**：APScheduler 每天 8 点自动生成日报。

**REST API**：FastAPI 暴露问答和体检接口。

**流式输出**：网页问答逐字显示，中间插入工具调用提示。

**Trace 日志**：每次 Agent 调用的工具名、参数、返回摘要写进 `logs/trace_日期.log`。

### 没做（MVP 范围外）

- 多轮对话记忆（单轮问答够用，后续可加）
- 对接淘宝/抖音/拼多多真实 API
- 多用户和权限系统（纯 CRUD，对这个项目的技术亮点没帮助）
- 实时数据流（用的是历史静态 mock 数据）
- 自动执行营销动作（改价、投流）
- 评论聚类用的是 LLM 直接聚，没上 embedding + KMeans

## 指标定义

| 指标 | 公式 |
|------|------|
| GMV | SUM(订单实付金额)，退款前口径 |
| 客单价 | GMV / 订单数 |
| UV | 流量表 UV 求和 |
| 转化率 | 下单 UV / UV |
| 加购率 | 加购数 / UV |
| 退款率 | 退款订单数 / 总订单数 |
| 差评率 | 评分 ≤3 星 / 总评论数 |
| 环比 | (本期 - 上期) / 上期 |

## 异常阈值（可在 config.py 改）

- 差评率 ≥15% 报警，≥30% 算 high
- 退款率 ≥10% 报警
- GMV 环比跌 ≥30% 报警；如果同时库存为 0，判定为疑似断货
- 全店差评率环比升 ≥8 个百分点报警
- 全店退款率环比升 ≥5 个百分点报警

## 归因思路

Agent 的 system prompt 里写死了排查路径：

```
异常商品
├── 库存 0 且已售罄 → 断货，建议补货
├── 库存正常 → 看差评聚类
│   ├── 主题集中在破损/漏水/快递 → 物流包装问题
│   └── 主题集中在质量/尺码/色差 → 商品和详情页问题
└── GMV 跌但差评正常 → 流量或渠道问题
```

## 数据

SQLite 模拟数据，45 天，8 个商品，5 个渠道（搜索/推荐/直播/广告/直接），约 4100 订单、2300 评论、210 退款。预埋了 3 个异常：

1. P1008 保温杯第 35 天起物流破损：转化率砍半、差评激增、退款率 26%
2. P1004 耳机第 20 天直播渠道 UV 翻 7 倍（正面异常，营销活动）
3. P1006 台灯第 40 天起断货：转化率 0、库存 0、状态已售罄

## 非功能要求

- 单次问答 5-8 秒（含流式）
- 全量体检 25-35 秒
- 指标计算 100% 正确（确定性代码，不经过 LLM）
- 数据工具只读，Agent 不能改业务数据
- API key 走 .env，不入库不入日志
