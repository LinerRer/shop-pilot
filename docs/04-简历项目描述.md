# ShopPilot 项目（简历用）

## 项目一句话

**ShopPilot：基于 MCP 协议与 LangGraph 的电商智能运营 Agent**（个人独立开发，2026.10）

## 简历 Bullet（按 STAR 写，可直接复制）

- 主导设计并实现基于 **MCP（Model Context Protocol）协议**的电商垂直智能体，使用 **LangGraph ReAct 框架**编排 DeepSeek 大模型；自研 FastMCP 数据服务对外暴露 7 个业务工具（GMV/转化率/退款率查询、趋势、渠道拆分、商品排行、异常扫描），支持自然语言经营问答与一键自动体检。

- 设计"**确定性计算归代码、语义归因归大模型**"的分层架构：用 SQLAlchemy + pandas 实现经营指标计算与阈值异常扫描，将关键数字从模型幻觉中隔离，对物流破损、断货等预埋故障的异常召回率达 100%。

- 实现 Agent 多步工具调用闭环：自动扫描异常清单 → 下钻商品详情 → 读取差评原文 → 根因归因（区分断货/物流包装/商品质量）→ 输出可执行运营建议，单次体检自主完成 6+ 次工具调用与多轮推理。

- 交付 **Streamlit 三 Tab 交互界面**（智能问答/一键体检/经营图表）与 python-docx 自动 Word 日报生成脚本，形成从数据接入到业务交付的完整 AI 应用闭环。

## 面试高频追问（准备好这些回答）

**Q1：为什么用 MCP？直接把数据库查函数写进 Agent 不行吗？**
MCP 是标准化的工具协议，工具服务和 Agent 解耦：数据服务可以独立部署、被多个 Agent/客户端复用，也符合企业里"数据中台服务化"的做法。直接写函数会把数据逻辑和 Agent 逻辑耦死。

**Q2：怎么防止大模型编数字？**
分层：指标、阈值、异常判断全部在 Python 代码里算死，模型只负责"理解问题、决定调哪个工具、读结果给建议"。模型永远拿代码算出来的真实数据，不让它自己算 GMV。

**Q3：ReAct 是什么？你的 Agent 怎么工作的？**
ReAct = Reasoning + Acting。模型每轮先"想"下一步该干嘛，决定调哪个工具，拿到结果再继续想，直到能回答问题。我的体检流程就是它自己一步步决定：先扫异常→发现 P1008/P1006→分别查详情→归因→写报告。

**Q4：异常召回是怎么做的？**
两步：代码里的 `scan_anomalies` 按固定阈值（差评率≥15%、退款率≥10%、GMV 环比跌≥30%、库存 0 售罄）确定性扫出候选异常；Agent 再对 high 级异常下钻详情做根因。确定性扫描保证不漏，LLM 负责解释。
