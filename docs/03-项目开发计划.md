# ShopPilot 开发记录

版本 v3.0，2026-10-13

原计划 7 天冲刺，实际 2 天高强度完成核心功能，之后追加了工程化和功能增强。下面按时间线记录做了什么、遇到什么问题、怎么解决的。

## Day 1：环境 + 数据层

PyCharm 中文界面，venv 建在 `D:\projects\shop-pilot`，Python 3.11（基础解释器 C:\Python311）。pip 走清华源。

写了 models.py（SQLAlchemy 2.0，7 张表）和 seed.py（45 天 mock 数据，random.seed(42) 可复现）。8 个商品、5 个渠道，预埋 3 个异常：P1008 物流破损、P1004 直播流量暴涨、P1006 断货。

**踩坑**：seed.py 第一次运行报 `unable to open database file`。原因是 `sqlite:///data/shop.db` 用的相对路径，PyCharm 运行时工作目录和预期不一样。改成 `Path(__file__).resolve().parents[2]` 算绝对路径，所有入口统一。

验证：商品 8 / 订单 4111 / 流量 1800 / 评论 2289 / 退款 213。verify.py 确认三个异常都成立。

## Day 2：MCP 数据查询 Server

**踩坑**：`pip install mcp` 默认装到 2.x，FastMCP 改名 MCPServer，API 全变，网上资料还是 1.x 的。降级到 `mcp==1.30.0`（`pip install "mcp<2"`），用 FastMCP。

写了 metrics.py（确定性指标计算：GMV/客单价/UV/转化率/加购率/退款率/差评率 + 环比，加了 lru_cache）和 ecomdb_server.py（6 个数据工具）。用原生 MCP ClientSession 写了 test_client.py，逐工具调通。

## Day 3：Agent + 体检归因

装了 langchain-mcp-adapters 0.3.2。config.py 用 pydantic-settings 读 .env 里的 DeepSeek key。

先用 create_react_agent + MultiServerMCPClient 跑通最小对话 Agent——输入"昨天 GMV 多少"，DeepSeek 自己决定调 get_metrics，回答正确。

**问题**：体检时纯靠 LLM 自主发现异常，漏掉了 P1006 断货（差评率不高但 GMV 跌，LLM 没关联到库存）。

**决策**：加确定性的 scan_anomalies 工具，阈值写死在代码里（GMV 环比跌 ≥30% 且库存 0 = 疑似断货），Agent 第一步必须先调它拿异常清单，再下钻归因。召回稳定了。

health_check.py 一键体检能正确召回 P1008 物流破损和 P1006 断货，并给出归因和建议。

## Day 4：网页 + 日报

app.py 写了 Streamlit 三 Tab：智能问答 / 一键体检 / 经营图表。

**踩坑**：点发送报 `RuntimeError: Event loop is closed`。Streamlit 同步脚本里直接 `asyncio.run()` 调异步 Agent，第一次后循环关闭，MCP 连接绑死旧循环。

**解决**：问答流式用 `nest_asyncio.apply()` + 主线程 `asyncio.run()` + `astream_events()`；体检非流式用 `ThreadPoolExecutor` 独立线程，每个线程全新循环。

generate_report.py 用 python-docx 生成 Word 日报（异常表格 + AI 根因建议），输出到 output/。

## Day 5：工程化升级

一口气做了 7 项：

1. 配置集中管理——路径、阈值、日期窗口、温度全部收进 config.py
2. Git 初始化 + .gitignore（排除 .venv / .env / data/*.db / logs / output / .idea）

6. 定时任务——scheduler.py + APScheduler，每天 8 点自动跑
7. FastAPI 接口——api.py，/api/ask、/api/health、/api/healthz，uvicorn 启动验证 healthz 返回 200

注册了 GitHub（用户名 LinerRer），初始化仓库，首次 push。

## Day 6：功能增强

做了 3 项：

1. **评论聚类 MCP Server**——review_server.py，工具 cluster_reviews，从 DB 读差评 → DeepSeek 聚类 → 输出主题+数量+样例。实测 P1008 保温杯 36 条差评聚成 9 个主题（包装简陋 8 / 快递暴力 4 / 漏水 5 / 保温差 3 等），坐实物流包装问题。接入了体检、网页、日报、API 的所有入口。

2. **异常主动推送**——utils/notifier.py，支持飞书/钉钉 webhook，没配就模拟打印。日报跑完如果有 high 异常就推送。实测模拟推送 7 条高级异常。

3. **流式输出**——app.py 用 astream_events(version="v2") 逐 token 输出，中间插入工具调用提示，光标 ▌。

## 关键决策记录

| 决策点 | 选择 | 原因 |
|--------|------|------|
| Agent 框架 | create_react_agent，不手写 StateGraph | 7 天冲刺，稳定，自带并行工具调用 |
| 评论聚类 | LLM 直接聚，不上 embedding+KMeans | 省模型下载调试，效果够用 |
| MCP 版本 | 锁 1.30.0 | 2.x API 不兼容 |
| 异常检测 | 确定性 scan + LLM 归因 | 保证召回率，不看 LLM 心情 |
| 可观测 | 自研文件 Trace，不用 Langfuse | 轻量，不依赖外部服务 |
| 多用户/账号 | 不做 | 纯 CRUD，对技术亮点没帮助 |
| GitHub 推送 | SSH 22 端口，不用 HTTPS | 443 被封，22 通 |
