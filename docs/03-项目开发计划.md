# ShopPilot 开发过程与技术决策记录

版本 v2.0，2026-10-13

本文档记录项目开发过程中各模块的实现思路、遇到的问题和技术决策。

## 数据层

用 SQLAlchemy 2.0 建了 7 张表：products、orders、order_items、traffic（按天×渠道×商品）、reviews、refunds、daily_reports。

Mock 数据用 `random.seed(42)` 保证可复现，覆盖 45 天经营数据，8 个商品、5 个渠道（搜索/推荐/直播/广告/直接），约 4100 订单、2300 评论、210 退款。预埋了 3 个异常供检测演示：P1008 物流破损、P1004 直播流量暴涨、P1006 断货。

**踩坑**：seed.py 运行报 `unable to open database file`。原因是 `sqlite:///data/shop.db` 相对路径依赖运行目录，PyCharm 和终端的工作目录不同。统一用 `Path(__file__).resolve().parents[2]` 计算项目根的绝对路径，所有入口一致。

verify.py 验证三个异常都成立：P1008 物流破损后订单腰斩、差评率 40%；P1004 直播 UV 达 581；P1006 断货后 0 单。

## MCP Server 开发

**踩坑**：`pip install mcp` 默认装到 2.x，FastMCP 改名 MCPServer，API 全变，网上资料还是 1.x 的。降级锁定 `mcp==1.30.0`（`pip install "mcp<2"`），用稳定的 FastMCP 接口。

### ecomdb_server（数据查询，7 个工具，只读）

list_products、get_metrics、get_trend、get_channel_breakdown、get_product_ranking、get_product_detail、scan_anomalies。

指标计算全部在 analytics/metrics.py 用 Python 确定性实现（GMV/客单价/UV/转化率/加购率/退款率/差评率 + 环比），加了 lru_cache。MCP Server 只负责暴露工具，不掺杂业务逻辑。

用原生 MCP ClientSession 写了 test_client.py，逐工具调通验证。

### review_server（差评聚类，1 个工具）

cluster_reviews(product_id, days)：从 DB 读差评，截断 3000 字后发给 DeepSeek，要求输出严格 JSON 的主题聚类。Prompt 约束主题名要具体（"物流破损""漏水"），禁止"其他问题"这类泛泛标签。

没上 embedding + KMeans，项目初期优先保证主链路跑通，LLM 直接聚类效果够用。实测 P1008 保温杯 36 条差评聚成 9 个主题（包装简陋 8 / 快递暴力 4 / 漏水 5 / 保温差 3 等）。

## Agent 开发

用 LangGraph create_react_agent + MultiServerMCPClient，DeepSeek 作为推理模型。

先跑通最小对话 Agent：输入"昨天 GMV 多少"，模型自主决定调 get_metrics 并正确回答。

**问题**：体检时纯靠 LLM 自主发现异常，漏掉了 P1006 断货——它差评率不高但 GMV 跌了，LLM 没关联到库存。

**决策**：加确定性的 scan_anomalies 工具，阈值写死在代码里（GMV 环比跌 ≥30% 且库存 0 = 疑似断货），Agent 第一步必须先调它拿异常清单，再下钻归因。召回从"看 LLM 心情"变成稳定。

health_check.py 一键体检能正确召回 P1008 物流破损和 P1006 断货，并给出归因和建议。体检时对多个 high 异常商品并行调 get_product_detail（ReAct + DeepSeek 的 parallel tool calling），Trace 日志可证同轮发起。

### 为什么用 create_react_agent 而不是手写 StateGraph

原计划手写 LangGraph 状态机（understand → router → attribution 循环），但手写要自己管工具调用循环、错误重试、步数限制，调试成本高。create_react_agent 是官方封装的稳定 ReAct 循环，还自带并行工具调用。面试讲 ReAct（Reasoning + Acting，模型自主决定调哪个工具）一样有技术深度。

## 界面与日报

Streamlit 三 Tab：智能问答（流式输出）、一键体检、经营图表（Plotly）。

**踩坑**：点发送报 `RuntimeError: Event loop is closed`。Streamlit 同步脚本里直接 `asyncio.run()` 调异步 Agent，第一次后循环关闭，MCP 的 stdio 连接绑死旧循环。

**解决**：问答流式用 `nest_asyncio.apply()` + 主线程 `asyncio.run()` + `astream_events()` 逐 token 输出；体检非流式用 `ThreadPoolExecutor` 独立线程，每个线程全新事件循环。

generate_report.py 用 python-docx 生成 Word 日报（异常表格 + AI 根因建议），写完自动存 daily_reports 表。

## 工程化

1. **配置集中管理**：路径、异常阈值、日期窗口、模型温度全部收进 utils/config.py（pydantic-settings），改配置不改业务代码
2. **Git 规范**：.gitignore 排除 .venv / .env / data/*.db / logs / output / .idea
3. **Trace 日志**：utils/trace.py，每次工具调用的名称、参数、返回摘要写 logs/trace_日期.log
4. **历史报告入库**：daily_reports 表，支持回看
5. **定时任务**：scheduler.py + APScheduler，每天 8 点自动生成日报
6. **REST API**：api.py + FastAPI，/api/ask、/api/health、/api/healthz
7. **异常推送**：utils/notifier.py，飞书/钉钉 webhook，没配就模拟打印到控制台

## 功能增强

- **评论聚类接入**：review_server 接入体检、网页、日报、API 所有入口，体检报告引用聚类结果
- **流式输出**：问答逐字显示，中间插入工具调用提示，光标 ▌
- **异常主动推送**：日报跑完如果有 high 异常自动推送

## 关键决策记录

| 决策点 | 选择 | 原因 |
|--------|------|------|
| Agent 框架 | create_react_agent，不手写 StateGraph | 稳定，自带并行工具调用，调试成本低 |
| 评论聚类 | LLM 直接聚，不上 embedding+KMeans | 优先保证主链路，效果够用 |
| MCP 版本 | 锁 1.30.0 | 2.x API 不兼容且资料少 |
| 异常检测 | 确定性 scan + LLM 归因 | 保证召回率稳定，不依赖 LLM 自主发现 |
| 可观测 | 自研文件 Trace，不用 Langfuse | 轻量，不依赖外部服务 |
| 多用户/账号 | 不做 | 纯 CRUD，对技术亮点没帮助 |
| GitHub 推送 | SSH 22 端口 | HTTPS 443 被封，SSH 稳定 |
